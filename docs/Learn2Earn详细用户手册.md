# Learn2Earn 详细用户手册

版本：2026.08 图文知识产品版  
适用对象：学习者、知识创作者、课程顾问、个人创业者、内容运营人员  
核心目标：把学习过程沉淀为可复用笔记，再把笔记转化为可编辑、可交付、可销售的 Word 知识产品。

---

## 1. 软件概览

Learn2Earn 不是单纯的记事本，也不是只负责“让大模型写一篇文章”的对话框。它把知识生产拆成一个连续工作流：创建学习科目，记录或导入图文笔记，整理学习阶段，选择知识产品类型，装载适用的 Skills、算法与质量技术，把耗时生成任务提交到后台，最后检查产品并导出 Word。用户可以在生成过程中继续查看其他笔记、整理科目或处理产品，页面切换不会主动中断后台任务。

软件左侧主导航包含工作台、科目管理、产品库、生成任务、Skills 仓库和 LLM 设置。工作台负责总览；科目管理负责组织学习主题；笔记位于科目内部；产品库汇总已经生成的交付件；生成任务集中显示排队、运行、完成和失败状态；Skills 仓库管理可供大模型参考的专业工作方法；LLM 设置连接实际的大模型服务。

系统中的三类核心对象是“科目、笔记、产品”。科目是容器，例如“短视频运营”或“Python 自动化”；笔记是原始知识资产，可以手工编辑，也可以从 DOCX 导入；产品是对笔记进行结构化加工后的商业交付物。三者之间保留关联，因此从产品可以追溯源笔记，导出时也能读取源笔记插图。

## 2. 初次使用与账号

打开应用后，未登录用户会进入登录或注册界面。注册时填写可用邮箱和密码；登录成功后，访问令牌保存在当前浏览器的本地存储中，后续 API 请求自动携带身份信息。点击侧栏底部“退出登录”会清除令牌并回到登录状态。不要在公共电脑上长期保留登录状态。

每位用户的数据相互隔离。科目、笔记、产品、笔记图片、Skills 和生成任务都带有用户归属。即使两个用户使用相同文件名，资源读取也会按登录身份校验。图片接口支持鉴权令牌，因此编辑器能显示私有插图，但其他用户不能只凭资源编号读取图片。

首次使用建议依次完成三件事：在 LLM 设置中配置并测试一个可用模型；在 Skills 仓库中导入知识付费 Skills 包；在科目管理中创建第一个科目。若没有配置可用模型，仍可整理和导入笔记、查看既有产品与导出 Word，但新的 AI 生成任务会失败并在任务中心展示原因。

## 3. 工作台

工作台是登录后的信息总览。顶部统计展示学习科目数、笔记数、知识产品数和估算潜在收入。潜在收入是根据产品建议价格进行的汇总，用于快速观察知识资产规模，不等同于实际到账收入，也不构成收益承诺。

“学习科目”区域显示最近或常用科目，点击卡片进入对应笔记列表。“最近笔记”用于快速返回近期内容。“最新产品”用于打开最近生成或修改的产品。产品状态通常分为草稿和已发布；发布状态是内容管理标记，不会自动把产品上传到第三方平台。

当账号还没有科目时，工作台显示创建入口。推荐先按稳定主题建立科目，而不是为每篇笔记创建一个科目。例如，把“直播话术”“直播复盘”“直播选品”都放进“直播运营”科目，更利于后续搜索、产品组合和跨笔记复用。

侧栏底部展示笔记数量、产品数量和潜在收益。该区域是快速指标，不替代产品库中的详细检查。数据更新通常在创建、保存、导入或生成完成后刷新；如果刚提交后台任务，产品数要等任务真正完成并写入产品后才会增加。

## 4. 科目管理

进入“科目管理”可查看全部学习科目。每个科目包含名称、图标、描述、主题色、笔记数量、累计学习时间、创建时间和最后修改时间等信息。名称应体现长期主题；描述可写学习目标、受众和变现方向；图标与颜色用于视觉区分。

点击“新建科目”打开创建表单。填写名称是最低要求。建议在描述中明确三个要素：要掌握什么、服务谁、可能形成什么产品。例如：“整理面向零基础运营人员的小红书起号方法，最终形成起号 SOP、选题模板和复盘表。”清晰的科目描述也能为后续生成提供上下文。

科目列表顶部支持按名称搜索。输入关键字后，列表即时缩小；清空搜索框恢复全部。排序支持最后修改时间、名称和大小。按最后修改时间排序适合继续最近项目；按名称排序适合固定目录式管理；按大小排序使用科目所含内容规模的估算值，适合识别大型知识库。排序方向按钮可在升序和降序间切换。

“大小”不是操作系统文件夹占用空间的精确字节数，而是根据科目内容和关联数据形成的可比较指标。它的用途是排序，不应用作存储计费依据。科目的最后修改时间会随着科目资料或关联内容变化而用于列表排序。

点击科目卡片进入笔记列表。删除科目前应先确认关联数据影响；重要内容建议先导出产品或保留源 Word。编辑科目名称不会切断已有笔记和产品关联，因为内部使用稳定编号关联。

## 5. 学习笔记列表

科目内部的笔记列表展示标题、标签、学习阶段、预计学习时间、内容摘要、大小与更新时间。顶部提供新建笔记入口，并提供名称搜索、排序字段和排序方向控件。搜索按笔记标题匹配，适合用文件名或标题中的关键词定位资料。

排序字段包括最后修改时间、名称和大小。最后修改时间用于继续最近编辑的内容；名称适合按课程章节编号组织，例如“01-定位”“02-选题”；大小用于发现长笔记或包含较多内容的笔记。若要形成稳定的课程目录，可在标题前使用两位数字编号，再按名称升序排列。

列表中点击笔记进入编辑器。删除按钮只应在确认后使用；删除源笔记可能影响产品追溯和源插图复用。已经导出的 Word 不会被远程召回，但系统内的产品再次导出时可能无法取得被删除笔记的图片，因此产品交付完成前不要随意清理源笔记。

笔记列表的搜索只改变当前视图，不会删除或移动数据。若搜索不到内容，先清空搜索框，再检查是否进入了正确科目。排序同样只影响显示顺序，不改变笔记归属。

## 6. 文档式富文本编辑器

笔记编辑界面采用文档式布局：顶部是返回、面包屑、导入 Word 和保存；中间是白色文档画布；右侧是笔记助手与统计。相比纯文本输入框，该编辑器能直接呈现标题层级、段落、表格、图片、列表、引用和行内格式，接近主流知识库软件的创作体验。

标题输入位于文档顶部。标题应简洁且可检索，不建议把全部摘要放进标题。元数据区包含学习阶段、预计学习分钟数和标签。标签用逗号分隔，可以写主题、来源、受众或用途，例如“Word导入, 小红书, SOP”。预计学习时间是计划值，可用于工作台和科目统计。

工具栏包含粗体、斜体、行内代码、一级标题、二级标题、无序列表、有序列表、引用、插入图片、插入表格、撤销和重做。选中文字后使用粗体或斜体；标题按钮用于建立真正的文档层级；列表适合步骤或要点；引用适合来源摘要和重要原话；行内代码适合命令、变量或提示词片段。

插入表格会创建 3×3 的可编辑表格。表格用于真正需要行列比较的信息，例如阶段、目标和交付，不要把长篇正文全部塞进单元格。表格可以与标题、段落和图片混排。撤销与重做不会改变工具栏尺寸，避免编辑时界面跳动。

插入图片按钮允许从本地选择图片。新建笔记尚未保存时，应先保存一次以取得稳定笔记编号，再上传长期图片；从 Word 导入时，图片资源会随导入流程自动保存并绑定笔记。图片显示在正文的光标位置或文档对应位置，导出产品时可根据插图标记复用。

编辑器正文变化后，系统同时维护富文本 HTML 和纯文本内容。HTML 用于所见即所得显示；纯文本用于大模型理解、搜索摘要和兼容旧数据。保存时会清理鉴权查询参数并进行 HTML 安全过滤，避免把临时令牌写进数据库。

点击“保存”后出现成功提示。新建笔记首次保存会自动把地址替换为该笔记的编辑地址；后续保存更新原记录。标题或正文为空时不会提交。离开页面前应确认看到“笔记已保存”，以免未保存修改丢失。

右侧笔记助手显示正文字符数和当前学习阶段，并说明 Word 图文与产品生成的关联。已保存笔记可以点击“进入产品生成中心”；新建但未保存的笔记没有稳定编号，因此按钮暂不可用。

## 7. Word / DOCX 图文导入

点击编辑器右上角“导入 Word”，选择扩展名为 `.docx` 的文件。系统只接收 Office Open XML 格式，不支持旧版 `.doc`。单个文件上限为 30MB。导入过程会解析段落、标题、表格和内嵌图片，并尽量保持它们在正文中的原始顺序。

系统不是简单提取 Word 的纯文本。解析器遍历文档主体块，区分段落和表格；标题样式被转换为富文本标题；表格被转换为 HTML 表格；图片从 DOCX 压缩包中提取为私有笔记资源。导入完成后，界面提示识别出的插图数量，并跳转到新笔记的编辑页。

图片保存时会记录文件名、媒体类型、大小和源位置锚点。正文 HTML 使用受保护的资源地址，编辑器在显示时临时加入当前登录令牌。纯文本上下文中会加入类似“插图 1、位置 block-X”的标记，让生成器知道图片应该跟随哪一段知识，而不是只知道“文档里有一张图”。

Word 中的表格会在编辑器里直接呈现，而不会退化为难读的制表符文本。复杂 Word 特性，例如浮动文本框、SmartArt、宏、修订气泡、嵌入对象或高度定制的页眉页脚，不属于当前导入保证范围。建议在导入前把关键内容转为普通段落、表格和行内图片。

导入会创建一篇新笔记，不会覆盖当前正在编辑的笔记。文件名去掉 `.docx` 后作为初始标题，标签自动包含“Word导入”，预计学习时间按正文长度估算。导入后可以继续使用富文本工具修改标题、表格、段落和标签，再点击保存。

若提示“仅支持 .docx”，请在 Word 中使用“另存为”并选择 DOCX。若提示超过 30MB，可压缩图片或拆分文档。若解析失败，原文件不会被修改；系统会清理本次未完成导入产生的临时资源。对于来源不明的文档，应先用安全软件检查，因为系统只读取文档内容，不应把 DOCX 当作可执行包。

## 8. Markdown 兼容与表格显示

历史笔记或历史产品可能以 Markdown 保存。展示层使用支持 GFM 的解析能力，因此形如竖线分隔的 Markdown 表格会渲染为真正的表格。表头、边框、单元格内边距和横向溢出都有专门样式，在窄屏或宽表情况下保持可读。

标准表格写法应包含表头分隔行，例如：第一行写字段名，第二行使用 `---` 分隔，后续每行写数据。缺少分隔行的内容不一定会被识别为表格。单元格内包含竖线时需要转义。新编辑器保存的是富文本 HTML，历史 Markdown 则在加载时转换为安全 HTML，因此新旧内容可以共存。

产品查看页也启用了 GFM 表格插件。表格不再以一串竖线原样显示。产品正文仍以 Markdown 为主要生成载体，标题、列表、引用、代码和表格会统一渲染；导出 Word 时再转换为 Word 的段落与表格结构。

## 9. 学习阶段术语详解

“筑基期、专精期、融合期、创业期”描述的是知识从入门到商业化的成熟程度，不是对人的身份评判，也不是必须按日历时间严格推进的课程等级。一名用户可能在写作上处于融合期，在数据分析上仍处于筑基期。

筑基期的目标是建立基础概念和最小实践能力。此阶段笔记应回答“它是什么、为什么重要、怎样完成第一个可运行示例”。合适的产品包括入门清单、术语表、快速上手教程和基础提示词。判断标准不是看过多少材料，而是能否独立完成一个小任务并解释关键概念。

专精期的目标是围绕一个明确方向进行深度训练，形成稳定、可重复的技能。笔记应记录边界条件、常见错误、评估指标、案例和复盘。合适的产品包括专项 SOP、模板、检查表、进阶教程和垂直领域提示词。用户所问的“专精期”就是从广泛了解转向单项能力的可靠交付阶段。

融合期的目标是把多个单项技能组合成完整产品或解决方案。例如把选题、写作、排版、发布和数据复盘组合成小红书起号工作流。笔记应说明各环节输入输出、依赖关系、失败回退和质量门槛。合适的产品包括端到端工作流、课程体系、知识库和跨工具自动化。“融合期”强调组合，不是简单把多篇笔记拼在一起。

创业期的目标是形成品牌、产品矩阵和可持续商业闭环。此阶段不仅关注内容质量，还关注用户画像、定价、渠道、交付成本、复购、合规和迭代。产品可能是系列课程、会员知识库、咨询交付包、软件教程与分销方案。进入创业期不意味着必须注册公司，而是开始用经营视角验证价值。

选择阶段时按当前笔记的成熟度判断。若内容主要是概念摘录，选筑基期；若是一项能力的深入方法，选专精期；若串联多个能力解决完整问题，选融合期；若已经包含市场、定价、销售和复购设计，选创业期。阶段可随内容成熟而修改。

## 10. 知识产品生成中心

从已保存笔记进入产品生成中心。页面先展示可生成的产品类型，再展示生成策略。策略包括 Skills、算法和质量技术，三组都支持多选。未主动选择时，系统根据产品类型填充默认策略；主动选择后，以用户选择为准。

产品类型覆盖传统知识产品和新增交付物，包括电子书、在线课程、咨询方案、会员内容、模板工具包、训练营、PPT 模板、日程表模板、演讲准备 SOP、提示词模板、工作流、做课 SOP、小红书起号 SOP、IMA 知识库、一人公司 SOP、LLM Skills、软件使用教程等。界面从后端读取类型定义，因此名称、图标、价格区间、推荐平台与生成蓝图保持一致。

选择产品时应匹配源笔记结构。概念完整、章节清楚的长笔记适合电子书或课程；时间与任务信息适合日程表；明确步骤与验收标准适合 SOP；大量可复用指令适合提示词模板或 LLM Skills；工具操作、用户收益和推广路径齐全时适合软件使用教程。

生成方式包括快速生成、智能规划后确认、单个产品生成和一键生成多个产品。无论从哪个入口触发实际生成，最终都会创建持久化后台任务，而不是让浏览器页面一直等待。智能规划可以先分析笔记并给出推荐组合，用户确认后再提交任务。

提交成功后页面跳转到生成任务中心。此时可以切换到科目、笔记、产品库或 Skills 仓库，任务不会因为 React 页面卸载而中断。真正执行者在后端线程池中工作，任务状态和进度写入数据库。关闭当前标签页不会主动取消已经提交的任务；但如果整个后端服务进程被停止，正在运行的内存工作线程会终止，重启后仍能看到持久化任务记录及其最后状态。生产部署建议配合长期运行的进程管理与外部队列。

## 11. Skills、算法与质量技术

Skill 是一份面向大模型的专业工作说明，通常包含角色、步骤、约束、检查方法和输出格式。它不是简单的产品类型，也不是必须执行的程序。Learn2Earn 当前安全地读取 Skill 文本并把选中的说明加入生成上下文，不执行 ZIP 中的脚本。这样既能利用成熟方法，又避免上传内容直接获得服务器执行权限。

生成页的 Skills 区域列出当前启用的 Skill。点击标签可以多选，再次点击取消。选择并不是越多越好：过多且互相冲突的说明会挤占模型上下文，并降低重点。推荐选择一到三个高度相关的 Skill。例如生成课程可选择课程设计与质量验收 Skill；生成 PPT 模板可选择演示结构 Skill；生成软件教程可选择教程编写和分销披露相关 Skill。

算法描述“如何组织生成过程”。分层规划先建立结构和交付标准；分块生成把长内容拆成可控章节，降低一次生成过长导致的遗漏；迭代精修允许先出草稿再按质量报告改进；并行草拟适合多个相对独立的章节或方案。算法可多选，系统把选择作为 Agent 工作约束。

“是否使用分块生成”取决于内容规模。短提示词模板通常不必分块；两万字电子书、完整课程、知识库或多个 SOP 组合适合分块。分块不等同于把原文平均截断。合理分块按产品结构、主题边界和交付阶段划分，并在最后做跨块一致性检查。

质量技术描述“用什么手段提高可靠性”。源笔记约束要求内容以笔记事实和插图标记为依据；五维质量评分从完整性、准确性、可执行性、商业价值和表达质量等维度检查；反幻觉检查要求标记无法从来源确认的事实；SEO 优化面向需要公开分发的产品；示例驱动要求用案例、模板或完成示例降低理解成本。

每种产品类型拥有默认 Skills、算法和质量技术。默认值由后端策略接口集中返回，前端自动选中，因此新增类型不会依赖散落在页面里的硬编码。用户可以在默认基础上增减。软件使用教程默认更重视用户收益、步骤清晰、推广披露与来源约束；课程和电子书更适合分层规划、分块和一致性检查；模板类更重视可复制字段、示例和验收标准。

生成请求会记录选中的 Skill 编号、算法和技术。后台任务按用户身份读取启用 Skill 的完整指令正文，但 Skills 列表接口只返回管理所需摘要，不把私有指令无必要地暴露给所有页面。构造模型上下文时还设置总长度上限，避免一个超大 Skill 吞噬全部提示词空间。

## 12. Skills 仓库

“Skills 仓库”是用户专属的工作方法存储空间。页面展示 Skill 名称、描述、分类、启用状态和更新时间。可以上传自己的 ZIP，也可以点击“导入知识付费包”安装本机提供的 `workbuddy_skills_all.zip`。本次提供包能够发现近百个含 `SKILL.md` 的技能目录。

上传包必须是 ZIP，并在任意子目录中包含一个或多个 `SKILL.md`。每个文件可使用 YAML 前置信息声明 `name` 和 `description`；如果没有，系统会从标题或目录名推断。分类字段用于管理，例如“知识付费”“课程”“营销”。一个 ZIP 可以安装多个 Skills。

安全解压会拒绝 `../` 路径穿越、绝对路径和超出目标目录的文件。压缩包上限为 20MB，单个解压文件上限为 2MB，文件数上限为 2000。限制用于防止压缩炸弹、异常占用和覆盖服务器文件。安装失败时会清理对应目录，不留下半安装状态。

点击启用开关控制 Skill 是否出现在生成选择和后台加载结果中。暂时不用的 Skill 建议禁用而不是删除，便于以后恢复。删除 Skill 会移除数据库记录，并在路径确实位于专属 Skills 根目录时清理对应文件。系统不会根据上传 Skill 自动安装 Python 或 Node 依赖，也不会运行其中脚本。

一键导入知识付费包时，系统扫描真实 ZIP，发现所有 Skill，并按名称跳过已经安装的重复项。页面提示本次新增数量和发现总数。若重复导入没有新增，属于正常幂等行为，不表示原有 Skills 丢失。

编写自定义 Skill 时，建议包含：适用场景、不适用场景、输入要求、工作步骤、输出结构、质量检查和失败处理。避免写入 API 密钥、客户隐私或无关长资料。Skill 是方法层，具体笔记内容仍应放在笔记中。

## 13. 后台生成任务中心

任务中心集中显示所有生成工作。每个任务包含源笔记、目标产品类型、状态、进度、当前步骤、创建时间、开始时间、完成时间、失败原因和结果摘要。状态包括 queued（等待）、running（运行）、completed（完成）和 failed（失败）。

任务提交后先进入等待状态。执行器默认最多同时处理两个任务，更多任务排队，避免多个长生成同时耗尽模型配额和服务器资源。运行时先读取笔记、科目、选中 Skills 和策略，然后按产品类型逐个生成。多产品任务的进度会根据已处理类型逐步更新。

任务页面定时轮询最新状态，因此无需手动刷新。进度是流程估计值，不等于模型服务给出的精确百分比。当前步骤会显示“读取笔记与生成策略”“生成某类产品”“生成完成”或失败阶段。任务完成后，结果中的产品写入产品库。

重新生成产品也走后台任务。产品页点击重新生成时，系统带上原产品编号和类型创建任务；完成后更新该产品内容，而不是依赖原页面持续等待。用户可以马上离开产品页，在任务中心观察进度。这样解决了慢速生成时无法切换页面、切换后中断或丢失状态的问题。

失败任务不会悄悄消失。若 LLM 未配置、源笔记被删除、产品类型无效或上游模型报错，任务状态变为失败，并保留错误文本。处理方式是先修复配置或数据，再重新提交。当前版本不自动无限重试，以免重复消耗付费模型额度。

任务持久化意味着刷新浏览器仍可看到记录；后台执行本身当前采用应用进程中的线程池。正式生产环境若要求服务器重启后自动续跑、跨机器扩容和精确重试，可把执行器替换为 Celery、RQ 或云任务队列，现有任务表和前端任务中心可以继续作为状态契约。

## 14. 知识产品类型详细说明

电子书适合章节化知识、系统方法和案例集合。生成时应检查目录层级、章节衔接、练习与结论。在线课程除正文外还应包含学习目标、课时安排、作业、验收和课程交付提示。咨询方案强调问题诊断、范围、里程碑、交付物和风险。

会员内容适合持续更新的资料体系，需要说明更新频率、内容栏目和会员权益。模板工具包适合可反复复制的表格、清单、文案框架或操作表。训练营强调时间节奏、每日任务、打卡、反馈和结营标准。

PPT 模板不是把长文章逐段搬到幻灯片，而是给出封面、议程、章节页、核心信息页、案例页、数据页和结尾行动页的结构、占位内容与视觉建议。系统最终仍以 Word 形式交付文字化模板规范，用户可据此制作 PPT；“仅导出 Word”指应用统一交付格式，并不取消 PPT 模板这一产品品类。

日程表模板要明确时间粒度、任务、优先级、负责人、完成标准和复盘字段。演讲准备 SOP 覆盖受众分析、核心主张、论据、故事、幻灯片、排练、计时、设备检查和现场应急。提示词模板包含变量、使用说明、正反例、输出格式和风险提示。

工作流描述多个角色或工具之间的输入、动作、输出、判断分支和失败回退。做课 SOP 覆盖需求验证、课程定位、大纲、脚本、录制、剪辑、资料、上架、交付与复盘。小红书起号 SOP 覆盖定位、竞品、账号包装、选题、内容生产、发布节奏、互动、数据分析和合规。

IMA 知识库产品强调知识库目录、资料来源、命名规则、标签、问答入口、维护机制和检索提示。它交付的是可迁移的知识组织方案，而不是声称自动写入第三方 IMA 账号。一人公司 SOP 关注个人在获客、销售、交付、财务、客服和自动化之间的最小运营闭环。

LLM Skills 产品用于生成可被模型或智能体加载的技能说明，包含触发条件、工作步骤、工具边界、输出契约和测试样例。软件使用教程同时写清用户收益、功能介绍、操作步骤、常见问题和分销赚佣金路径；涉及佣金时必须透明披露推广关系，不得编造收益或隐藏风险。

## 15. 产品库与产品查看

产品库汇总全部草稿和已发布产品。顶部支持按产品名称搜索，并按最后修改时间、名称或大小排序。产品大小根据正文和关联内容估算，用于比较长短。搜索与排序可以组合，例如先搜“课程”，再按大小降序找出最完整的课程产品。

产品卡片显示标题、类型、状态、建议价格、推荐平台、关键词和更新时间。建议价格来自产品类型区间或生成结果，只是运营参考。推荐平台同样是建议，不表示系统已连接或代发到该平台。

打开产品后，正文使用安全的 Markdown 渲染器展示。GFM 表格会成为真正的 HTML 表格；标题、列表、引用和代码块具有统一排版。若正文包含源插图标记，页面保留对应语义，Word 导出服务会查找源笔记资源并插入图片。

产品可以标记发布、返回草稿、删除或重新生成。发布按钮只改变内部状态。删除前应先导出重要 Word。重新生成不阻塞当前页面，会进入任务中心；任务完成后再次打开产品查看新内容。

## 16. Word 导出与插图复用

产品页只保留“导出 Word”。Markdown 和 TXT 导出已移除，以减少用户面对多个不一致格式的复杂性，并集中保证 DOCX 的图文质量。点击按钮后浏览器下载以产品标题命名的 `.docx` 文件。

导出器读取产品正文、源笔记和笔记图片。Markdown 标题转为 Word 标题，普通段落转为正文，列表按条目写入，表格转为 Word 表格。遇到与图片相匹配的插图标记时，图片插入该位置附近。这样图片不只是被附带下载，而是回到与来源语义相符的段落。

如果产品生成结果遗漏了某个图片标记，导出器不会静默丢弃图片，而是在文末创建“源笔记插图”附录放入尚未使用的资源。这是保底机制：最佳结果是模型按标记把图片放到正文合适位置，最差仍保留源图片供人工调整。

Word 文件中的图片来自用户自己的源笔记。用户应确保拥有使用和销售这些图片的权利。系统不会自动判断版权、肖像权或商标许可。对外销售前，应逐张检查图片清晰度、敏感信息、授权范围和说明文字。

导出后建议执行交付前检查：打开 DOCX；更新目录（如有）；确认标题层级；检查表格是否跨页可读；确认每张图位于相关段落之后；删除无关附录图；检查价格、平台和推广披露；最后使用不同设备或 PDF 预览复核版式。

## 17. LLM 设置

LLM 设置用于添加、编辑、激活、测试和删除模型配置。配置通常包含名称、服务地址、模型名、API 密钥以及是否启用。具体字段以当前界面为准。只有激活且测试可用的模型会被生成服务正常调用。

添加配置后先使用“测试”功能，而不要直接提交大型生成。测试成功说明网络、鉴权和基本响应正常，不保证长文本配额充足。若使用兼容 OpenAI 协议的第三方服务，应确认其端点路径、模型名和响应格式兼容。

API 密钥属于敏感信息。不要写入笔记、Skill 或录屏。开发环境的本地数据库适合测试，不应直接作为多人生产密钥库。生产部署应使用环境变量、密钥服务、加密存储和最小权限策略。

模型选择影响质量、速度和费用。长文与复杂策略通常需要更大上下文和更强推理能力；短模板可用更快模型。后台任务让等待变得可管理，但不会降低模型实际调用成本。一次选择过多产品类型和 Skills 可能增加耗时。

## 18. 搜索、排序与文件管理方法

学习科目、学习笔记和知识产品三个页面都支持按名称搜索，并支持按最后修改时间、名称和大小排序。搜索忽略与名称无关的正文内容，目的是提供类似文件管理器的稳定行为。如果需要全文检索，可在后续版本增加专门索引，不应把名称搜索误解为全文搜索。

最后修改时间适合“继续工作”；名称适合“按目录阅读”；大小适合“盘点资产”。建议形成命名规则：科目用领域名；笔记用“序号-主题-版本”；产品用“受众-结果-产品类型”。例如“03-选题验证-v2”和“零基础运营-30天起号-SOP”。

排序方向影响结果顺序。名称升序通常是 A-Z、数字从小到大；更新时间降序把最新内容放前；大小降序把最大内容放前。中文名称排序由浏览器区域比较规则处理，特殊符号和表情可能排在预期之外，因此不要依赖图标承担章节编号。

大小是应用层估算值：笔记主要依据正文和资源信息，产品主要依据内容长度，科目根据关联规模。它适合相对排序，不等价于 DOCX 最终下载体积。图片压缩率、Word 样式和媒体格式会影响实际文件大小。

## 19. 推荐端到端工作流

第一步，创建科目并写清受众、学习目标和预期产品。第二步，把来源材料整理为 DOCX，使用真正的标题样式、普通表格和行内图片。第三步，导入 Word 后检查表格与图片顺序，补充标签、阶段和预计学习时间。

第四步，在编辑器中整理内容：用标题建立层级，用表格表达对比，用列表表达步骤，删除重复摘录，补充自己的验证结果。第五步，保存笔记并进入生成中心。第六步，选择一个最匹配的产品类型，再选择少量相关 Skills、适合内容长度的算法和必要质量技术。

第七步，提交后台任务并转去处理其他工作。第八步，在任务中心查看是否完成；失败时按错误修复。第九步，打开产品检查事实、结构、表格、图片标记和商业表述。第十步，必要时重新生成或人工编辑源笔记后再生成。

第十一步，导出 Word 并逐页检查。第十二步，根据销售渠道补充封面、品牌、版权、联系方式和推广披露。第十三步，实际交付后收集用户问题，把问题回写为笔记与 Skill 的质量规则，形成下一轮改进。

## 20. 故障排查

无法登录：检查邮箱和密码，确认后端服务可访问；清除过期本地令牌后重试。页面空白：打开浏览器开发者工具检查 API 地址，确认前后端端口与代理目标一致。数据看似属于其他账号：立即退出并核对部署数据库与认证模式，正常情况下所有表均按用户隔离。

Word 导入失败：确认是 DOCX、文件小于 30MB、未损坏；把复杂浮动对象转为行内图片；使用 Word“打开并修复”后另存。图片不显示：确认仍处于登录状态，刷新令牌；检查图片记录与源文件是否存在。表格不显示：历史 Markdown 必须包含 GFM 表头分隔行；Word 表格应为普通表格而非截图或嵌入对象。

保存提示正文为空：在编辑器输入实际正文，不能只填写标题。插入图片不可用：新笔记先保存以取得编号。生成任务立即失败：打开任务详情读取错误，最常见原因是 LLM 未配置或模型测试失败。任务一直等待：可能已有两个长任务运行；检查模型限流和后台进程。

切换页面后任务是否中断：正常不会。任务执行在后端，页面只轮询状态。关闭整个后端进程则会终止当前内存工作线程。重新生成后产品没变化：先确认任务已完成，再刷新产品页；若失败，旧产品内容会保留。

Skills 导入为零：若提示已发现但新增为零，说明同名 Skills 已安装；若提示没有找到 `SKILL.md`，检查 ZIP 目录结构；若提示不安全路径或文件过大，重新打包。选了 Skill 但结果无明显变化：减少互相冲突的 Skills，确认它处于启用状态，并选择与产品类型更相关的方法。

Word 导出没有图片：确认产品关联源笔记且源笔记有图片；检查生成正文是否含插图标记；即便标记缺失，正常情况下未使用图片会进入附录。若源笔记或图片文件已删除，则无法复用。导出文件打不开：重新下载，检查磁盘空间，避免下载过程中中断。

搜索没有结果：确认搜索的是名称而非正文；清空搜索框；检查所在科目。排序看起来不对：检查升降序按钮，以及“大小”为估算而非磁盘字节。中文数字章节建议使用补零编号。

## 21. 数据、安全与合规

上传的 Word、图片和 Skills 会保存到应用存储空间。部署者应配置备份、容量监控、访问权限和生命周期策略。删除数据库前应同步处理文件；迁移服务器时要同时迁移数据库和 `storage` 目录，否则笔记记录仍在但图片或 Skills 文件会缺失。

系统对资源访问进行用户校验，对 ZIP 做路径和容量限制，对富文本做安全过滤，并且不执行上传 Skill 中的脚本。这些措施降低风险，但不替代完整生产安全方案。公开部署还需 HTTPS、限流、审计日志、恶意文件扫描、数据库备份和依赖更新。

大模型可能产生错误或不准确表述。源笔记约束和反幻觉检查只能降低风险，不能替代人工审核。医疗、法律、财务等高风险内容不得未经专业复核直接销售。软件分销教程必须披露佣金关系，禁止承诺不切实际收益。

输入第三方资料前应确认版权许可。对个人信息、客户机密、未公开商业数据和 API 密钥进行脱敏。导出的 Word 是可传播文件，交付前检查文档属性、隐藏内容、批注和图片中的敏感信息。

## 22. 管理员与部署说明

开发环境由 FastAPI 后端和 Vite/React 前端组成。后端负责认证、数据、DOCX、Skills、生成任务和 LLM 调用；前端负责交互和轮询。SQLite 适合本地演示，迁移脚本提供云数据库表、索引与行级安全策略。多人生产环境应使用可靠数据库并执行迁移。

存储根目录下分为笔记资源和 Skills。用户目录名使用用户标识的 SHA-256 截断值，避免邮箱、冒号等字符在 Windows 路径中失效，也减少直接暴露用户标识。文件名还会经过安全清理。

后台线程池最大工作数当前为 2。可以根据模型限流、CPU、内存和并发用户调整。若采用多进程 Uvicorn，每个进程都会有自己的线程池，因此生产并发控制最好迁移到集中队列。任务表保留统一状态字段，便于替换执行器。

前端构建会提示主包体积较大，因为富文本、Markdown 和业务页面在同一入口。它不影响功能正确性，但规模继续增长时可按路由代码分割。依赖审计应区分实际使用面：当前使用 BrowserRouter 客户端模式，不使用 React Server Components 的服务端 Action；仍应定期升级并重新跑 GUI 回归。

## 24. 常见问题

问：专精期和融合期哪个更高级？答：它们表示不同成熟度。专精期追求单项能力稳定，融合期追求多项能力形成完整方案。没有稳定专精能力的融合通常只是拼接。

问：可以直接上传 Word 当作最终产品吗？答：Word 导入入口面向源笔记。导入后应检查、编辑，再进入生成中心形成产品。最终产品通过产品页导出 Word。

问：Word 里的图片会被大模型真正“看见”吗？答：系统提取图片并保留位置标记，把图文结构放入生成上下文。当前主要依赖图片位置、文件信息和邻近文本；模型是否具备像素级视觉理解还取决于所接 LLM 与后续多模态配置。导出服务本身会复用真实图片。

问：切换页面会不会停止重新生成？答：不会。重新生成创建后台任务，页面切换只停止当前页的显示，不停止后端执行。后端服务整体停止则不同。

问：为什么只导出 Word？答：统一格式可以集中解决表格、标题和插图问题，减少 Markdown、TXT 与 Word 三套不一致逻辑。Word 也便于用户继续编辑和商业交付。

问：能选择多个 Skills 吗？答：可以，但建议少而相关。系统也允许多选算法和质量技术，并为每个产品类型提供默认组合。

问：PPT 模板为什么仍导出 Word？答：产品品类描述的是内容用途；交付格式统一为 Word。Word 中提供逐页结构、版式规范和占位文案，用户再制作或导入演示工具。

问：能否搜索正文？答：当前明确提供按文件名或名称搜索。正文全文搜索不在本版范围，避免名称搜索和全文索引概念混淆。

问：大小排序的单位是什么？答：它是应用根据内容形成的估算大小，用于相对排序，不是最终 DOCX 文件字节数。

问：Skills 会执行代码吗？答：不会。加载器读取 `SKILL.md` 的方法文本，服务器不会执行上传脚本或自动安装依赖。

问：生成结果一定能直接销售吗？答：不能保证。用户必须审核事实、版权、隐私、合规、图片授权、价格和推广表述。软件提供生产工具，不替代经营与专业责任。

## 25. 结语

Learn2Earn 的核心价值不是一次生成更多文字，而是把来源、结构、方法、执行状态和交付格式连成可管理的知识生产线。高质量结果来自五个环节共同作用：可信的图文笔记、清晰的产品类型、少而相关的 Skills、适合内容规模的算法、严格的人工验收。

最稳妥的使用习惯是：先把源笔记做对，再让模型做结构化加工；让慢任务留在后台，把人的时间用于校验、判断和改进；只交付经过 Word 逐页检查的版本；把每次用户反馈反写为新的笔记规则或 Skill。这样，“学习过程变成赚钱过程”才不是一句口号，而是一套能够持续复用和升级的工作方法。

## 附录 A：页面与字段字典

工作台“学习科目”表示当前用户拥有的科目记录数；“学习笔记”表示笔记总数；“知识产品”表示产品总数；“潜在收入”是建议价格汇总。最近笔记和最新产品是快捷入口，它们不构成独立副本，编辑后仍更新原对象。

科目字段中，“名称”用于搜索和主标题；“图标”用于侧重识别；“描述”说明学习边界和目标；“颜色”用于视觉区分；“笔记数量”由关联笔记统计；“累计学习时间”由笔记预计分钟数等数据折算；“大小”用于列表比较；“最后修改时间”用于最近工作排序。

笔记字段中，“标题”来自手工填写或 Word 文件名；“content”保存富文本 HTML；“raw_content”保存适合检索和模型上下文的纯文本；“subject_id”指向科目；“tags”是标签数组；“learning_stage”保存 stage1 到 stage4；“estimated_minutes”是预计学习时间；“is_completed”表示学习完成状态；大小与更新时间供列表管理。

笔记图片字段中，“filename”是来源文件名；“media_type”是图片 MIME 类型；“storage_path”是服务器内部位置，不应直接暴露给普通页面；“source_anchor”记录 Word 块位置或编辑器上传来源；“size_bytes”记录原始字节数；“url”是经过鉴权的应用资源入口。

产品字段中，“title”是产品名称；“product_type”决定蓝图与默认策略；“content”是生成正文；“subject_id”和“note_id”保留来源关系；“price_suggestion”是建议价格；“platform_suggestion”是推荐平台数组；“keywords”用于运营标签；“status”区分草稿和已发布；更新时间、大小用于排序。

Skill 字段中，“name”是唯一识别名称；“description”用于选择前判断；“category”用于仓库分组；“instructions”是后台装载的完整方法正文；“storage_path”指向安全解压目录；“enabled”决定是否可用于生成。列表管理不需要展示完整指令，以减少界面噪声和不必要暴露。

任务字段中，“note_id”是源笔记；“product_id”在重新生成时指向待更新产品；“product_types”可包含一个或多个类型；“skill_ids”“algorithms”“techniques”记录策略；“status”“progress”“current_step”“error”构成可观察状态；“result”保存生成产品与质量信息；开始、完成和更新时间用于审计。

## 附录 B：实战一，从培训 Word 到在线课程

场景：讲师已有一份内部培训 Word，包含章节标题、能力对照表、流程截图和课后练习，希望形成可销售的在线课程说明书。首先建立“客户成功培训”科目，在描述中写明学员是新入职客户成功经理，目标是掌握首次交付流程。

整理源 Word 时，把章节名设置为标题 1，把子步骤设置为标题 2；能力对照使用真正表格；每张截图改为行内图片，并在图片前写一句说明。不要把整页流程保存为一张看不清的小图。保存为 DOCX 后从新建笔记页点击“导入 Word”。

导入完成后检查提示的图片数，向下滚动确认标题、表格、图片和图片后的段落顺序。把阶段设为融合期，因为培训把沟通、项目管理和产品知识组合成完整交付。补充“客户成功, 培训, 交付 SOP”标签，修改预计学习时间并保存。

进入生成中心，选择在线课程。Skills 选择课程设计、作业验收和内容编辑相关项；算法选择分层规划、分块生成和迭代精修；质量技术选择源笔记约束、五维评分、反幻觉检查和示例驱动。不要额外选择与营销无关的十几个 Skills。

提交任务后进入任务中心。任务运行期间可返回科目继续整理下一份资料。完成后打开产品，检查课程目标是否可测量、课时是否过长、作业是否有答案标准、截图标记是否出现在对应课程。必要时修订源笔记的模糊步骤，再重新生成。

导出 Word 后打开文件，确认截图实际嵌入。把公司机密示例替换为公开案例，补充封面、版权、讲师信息和退款规则。最终 Word 是可继续编辑的交付母版，可以再交给排版人员制作课件和学员手册。

## 附录 C：实战二，从运营笔记到小红书起号 SOP

场景：运营人员记录了账号定位、爆款拆解、选题库、发布记录和复盘结论，希望形成一套起号 SOP。创建“小红书运营”科目，笔记按“01-定位”“02-选题”“03-内容”“04-复盘”命名，使名称排序形成自然课程顺序。

每篇笔记用表格记录共同字段，例如发布时间、主题、封面、点击、互动和结论；用图片保存经过授权的案例截图；在截图附近写出为什么有效，而不只存图。学习初期的规则摘录标为筑基期，稳定选题方法标为专精期，端到端起号流程标为融合期。

生成时选择“小红书起号 SOP”。算法使用分层规划和分块生成：定位、包装、选题、生产、发布、互动、复盘分别成块，再做一致性检查。质量技术选择源笔记约束、反幻觉检查和示例驱动。Skill 可选择内容运营、营销心理、文案编辑等少量相关项。

产品检查重点包括：是否区分适用账号类型；是否给出每天和每周动作；是否有发布前检查；是否包含数据复盘阈值；是否提示平台规则可能变化；是否避免承诺“几天必爆”。案例图片需要脱敏并确认使用权。

若要把 SOP 作为付费产品，应在 Word 中增加版本号、更新日期、适用范围和不适用范围。平台规则变化后更新源笔记，再重新生成新版本。不要直接覆盖已交付版本，应在标题或封面保留版本标记。

## 附录 D：实战三，从软件学习记录到分销教程

场景：用户学习一款效率软件，记录安装、核心功能、典型流程、订阅方案和推广政策，希望制作软件使用教程。科目描述要写清目标读者、软件解决的问题，以及教程是否包含推广链接。

源笔记应把功能描述转换为用户收益。例如“支持批量导入”要进一步说明能减少什么重复工作、适合何种规模、有什么限制。操作步骤要包含起始状态、点击位置、预期结果和失败处理。截图放在操作说明之后，并遮盖账号、密钥和客户数据。

生成类型选择“软件使用教程”。Skills 可选择教程写作、文案编辑和推广策略；算法可用分层规划与迭代精修；质量技术选择源约束、示例和反幻觉。生成结果应包含好处描绘、功能介绍、完整流程、常见问题、适合与不适合用户、价格时效声明和佣金披露。

对分销部分进行人工合规检查。明确写出可能获得佣金，不把佣金伪装成中立推荐；不编造软件官方承诺；价格、功能和政策是可能变化的信息，应标注核对日期并建议读者访问官方页面确认。若软件处理敏感数据，还要说明权限和隐私注意事项。

导出 Word 后，逐步复现教程，确保每个按钮名称与当前版本一致。截图过时比没有截图更容易误导，应设定定期复查周期。把用户反馈的卡点写回源笔记和 Skill，下一版生成会更贴近真实使用。

## 附录 E：实战四，创建并使用自定义 Skill

场景：团队有一套成熟的“课程交付质量检查法”，希望每次生成课程都自动参考。建立文件夹 `course-quality`，其中创建 `SKILL.md`。前置信息写名称和描述，正文写触发条件、输入要求、检查步骤、输出格式和禁止事项。

质量 Skill 可以要求：先列学习成果；每个成果至少对应一个练习；每个练习有可观察验收标准；章节时长不超过目标范围；来源无法支持的事实必须标为待确认；最终输出质量报告。不要把整套课程正文塞入 Skill，正文属于笔记。

把文件夹压缩为 ZIP，在 Skills 仓库点击上传并选择分类。安装后确认名称、描述和启用状态。进入课程生成页，选择该 Skill；同时保留课程默认算法。提交后，后台按当前用户和 Skill 编号加载完整指令，将它加入模型上下文。

用一个小笔记先做 A/B 验证：一次不选 Skill，一次选择 Skill。比较学习成果、练习覆盖和验收标准，而不是只比较字数。如果 Skill 造成格式冲突，修改说明使优先级更明确；如果过长，删除背景叙述，保留可执行规则。

团队更新 Skill 时，当前版本可以删除旧项后重新上传，或使用新名称保留版本。名称中加入版本号有利于追溯，例如 `course-quality-v2`。生产环境还可以扩展版本管理和发布审批，但上传内容仍不应被服务器直接执行。

## 附录 F：内容质量评审表

来源一致性：产品的关键事实能否在源笔记找到；图片是否来自对应笔记；是否把推测写成事实；时效性信息是否标注核对日期。发现无来源数字、法规、价格或平台政策时，应人工验证或删除。

结构完整性：标题是否准确；开头是否说明受众和结果；章节顺序是否符合用户完成任务的顺序；每个章节是否有输入、动作和输出；结尾是否有检查或下一步。长产品还要检查跨章节术语一致。

可执行性：读者能否按步骤操作；步骤是否使用动作动词；是否提供必要材料、模板或示例；失败时是否知道怎样处理；SOP 是否有完成标准。只有观点没有动作的内容，不应包装成 SOP。

表达质量：段落是否过长；标题是否真实反映内容；表格是否用于比较而非装饰；术语首次出现是否解释；图片是否有邻近说明；是否存在重复、空洞口号或模型化套话。优先删减重复，而不是继续加字。

商业价值：产品解决的问题是否具体；受众是否愿意为节省时间、降低风险或获得结果付费；交付物是否比免费文章更可复用；建议价格是否与深度、稀缺性和服务成本匹配；营销描述是否诚实。

合规安全：版权、肖像、隐私和商标是否得到处理；高风险专业内容是否经过专业审核；推广佣金是否披露；是否包含密钥、内部地址、客户名单或未公开数据；图片是否泄露账号信息。

Word 交付：文件能否打开；目录和页码是否需要更新；标题层级是否正确；表格是否跨页可读；图片是否清晰且位置正确；附录是否包含遗漏图片；文档属性、批注和修订是否清理；文件名和版本号是否明确。

## 附录 G：移动端、键盘与可访问性

应用主要面向桌面知识生产，因为富文本编辑、宽表和生成策略需要较大空间。响应式样式会在较窄视口调整布局，文档画布和侧栏重新排列，按钮文字换行或收缩。移动端适合查看任务与产品、进行轻量修改；复杂 Word 导入和长表编辑建议使用桌面浏览器。

熟悉的编辑快捷键由浏览器与 TipTap 提供，例如撤销、重做、粗体等。界面不依赖用户记住快捷键，工具栏按钮均可完成主要操作。图标按钮带有标题提示，鼠标悬停可了解功能。不要在输入法组合状态中误触全局快捷键。

标题使用语义层级，表格使用真实表格节点，按钮使用按钮元素，表单输入带邻近标签。颜色不是唯一状态信号：任务同时显示文字状态和进度，Skill 选择同时有边框与状态变化。仍建议部署团队持续用键盘和屏幕阅读器做专项测试。

图片从 Word 导入时保留文件名，但来源图片未必有高质量替代文本。对外发布前，应在最终 Word 中为信息型图片补充说明；纯装饰图可以标为装饰。不要用一张图片承载无法复制的关键文字。

## 附录 H：备份、迁移与恢复

完整备份必须同时包含数据库和存储目录。只备份 SQLite 或云表会丢失图片与 Skill 文件；只备份 `storage` 会丢失关联关系。备份时记录应用版本和迁移版本，验证压缩包能解压，并定期做恢复演练。

从本地迁移到云数据库时先执行迁移 SQL，确认新表、索引和行级安全策略，然后迁移用户归属字段。图片和 Skills 可迁移到对象存储，但要保持资源编号与数据库记录对应，并更新服务层读取方式。迁移期间不要让两套应用同时写同一数据集。

恢复后抽查登录、科目数量、随机笔记、随机图片、Skill 启用状态、任务记录和产品 Word 导出。对于正在运行的内存任务，备份无法捕获线程执行状态；维护前应停止接收新任务，等待运行任务完成，或将它们标记为需要重新提交。

## 附录 I：版本升级注意事项

升级前阅读数据库迁移，备份数据，记录当前环境变量和 LLM 配置。后端依赖新增 `python-docx` 与 Pillow，用于 DOCX 和图片处理；前端新增 TipTap 与 GFM 支持。安装依赖后先跑后端测试和前端构建，再启动服务。

升级后重点验证旧 Markdown 笔记加载，因为系统会把历史内容转换为安全富文本；验证现有产品表格；验证旧用户资源权限；验证产品类型数量和默认策略；验证提供 Skills 包重复导入不会产生异常副本。

浏览器缓存可能保留旧 JavaScript。部署新前端后若页面与接口不匹配，执行强制刷新或清理站点缓存。开发环境代理目标通过 Vite 环境变量配置，验收时应避免复用历史端口上的旧服务。

依赖升级出现审计警告时，应结合实际使用路径评估，不要忽略，也不要在未回归情况下盲目跨大版本。每次升级至少重新完成 Word 导入、表格显示、Skill 导入、后台任务、三类搜索排序和 Word 图片导出的 GUI 验收。

## 附录 J：文档交付与反馈记录

本手册对应 2026.08 图文知识产品版本。重要行为包括：DOCX 图文导入、文档式富文本编辑、GFM 表格显示、仅 Word 导出、源图片复用、后台生成任务、Skills 仓库、多策略选择、新产品品类和三类资源搜索排序。后续界面或字段变化时应同步更新手册版本。

团队使用时，建议建立反馈记录，至少包含日期、账号环境、所在页面、操作步骤、预期结果、实际结果、截图或任务编号。涉及生成质量时，同时记录源笔记版本、产品类型、选择的 Skills、算法、质量技术和模型配置，才能复现实验差异。

功能问题与内容质量问题要分开：按钮无响应、导入失败、图片缺失属于功能问题；结构不佳、案例不足、措辞空泛属于内容质量问题。前者进入软件缺陷流程，后者优先修订笔记、策略或 Skill。清晰分类能避免反复重新生成却没有解决根因。

交付前最后确认：源笔记已保存；任务状态完成；产品事实已审核；表格和图片正确；Word 已下载并逐页打开；版权、隐私和佣金关系已检查；文件名含产品名与版本；原始资料、最终 Word 和反馈记录已进入备份。

本手册自身提供 Markdown 与 DOCX 两种版本。Markdown 便于版本控制和全文检索；DOCX 便于阅读、批注和内部交付。两者正文来源一致，DOCX 经过 Word 渲染逐页检查。以仓库中最新版本号和最后修改时间判断适用版本。
