## BUG-0810-01：14 篇科目进入后显示 0 篇

- 状态：Agent 自测通过。
- 现象与触发条件：工作台/科目管理显示“自媒体变现方法论”有 14 篇笔记，进入科目后列表可能为空。
- 根因：`Dashboard` 与 `NotesList` 共用 Zustand 的全局 `notes`；两个页面的异步请求可能后完成者覆盖先完成者，导致科目详情读取到未按当前科目过滤的共享状态。
- 受保护行为：科目详情必须拥有按 URL `subjectId` 查询的局部笔记状态；不得删除或修改用户科目和笔记来掩盖计数问题。
- 修改：`frontend/src/components/NotesList.jsx` 改为直接调用 `api.notes.list({ subject_id: subjectId })`，使用局部 `subjectNotes`、加载状态和卸载取消标记。
- 回归测试：`frontend/src/utils/regressionSurfaces.test.js` 的 `subject note page owns its filtered notes instead of sharing dashboard state`。
- 修复前证据：新增源码契约测试失败，页面仍调用共享 `fetchNotes({ subject_id })`。
- 修复后证据：真实账号中科目 ID 8 的 API 卡片计数/实际关联笔记/详情页标题均为 14，详情页渲染笔记卡片且不显示空状态。

## BUG-0810-02：重复 Skill 被再次安装和重复展示

- 状态：Agent 自测通过。
- 现象与触发条件：安装同名 Skill 时没有明确跳过；历史重复记录会在策略偏好搜索结果中重复出现。
- 根因：归档安装路径没有按规范化名称检查当前用户已安装记录；列表接口没有兼容历史重复数据。
- 受保护行为：名称经 Unicode NFKC、空白折叠和不区分大小写后相同的 Skill 只安装一次、只展示一次；重复项必须返回名称并在批量安装结果中明确提示。
- 修改：`backend/app/routers/workspace.py` 新增 `_skill_name_key`、`_dedupe_skills`，在安装、内置导入和列表读取路径统一去重；`frontend/src/components/SkillsManager.jsx` 展示批次及压缩包级重复项。
- 回归测试：`backend/tests/test_workspace_features.py` 的 `test_batch_upload_skips_duplicate_skill_and_reports_its_name`、`test_skill_list_hides_historical_duplicates`；`frontend/src/utils/regressionSurfaces.test.js` 的重复提示契约。
- 修复前证据：同一压缩包第二次安装仍返回 `installed == 1`。
- 修复后证据：第二次安装返回 `installed == 0` 和重复名称；真实账号 `/api/skills` 返回 98 个规范化后唯一名称，策略搜索数据源无重复。
