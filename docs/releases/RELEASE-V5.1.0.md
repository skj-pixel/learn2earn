# Learn2Earn V5.1.0 修复说明

- 修复分支：`release/v5.1`
- 基线：V5.0.0 `dacd7e5`
- 版本号：`5.1.0`

## 缺陷根因

1. `GET /api/skills` 混入了内置 Skill 包检测、解压和安装副作用。分类条件不满足时，每次列表或搜索都可能重复扫描压缩包；与后台生成并发时会争抢 CPU、文件系统和 SQLite。
2. Skills 仓库首次挂载发出两个重复请求，搜索也允许较早请求在较晚请求之后覆盖页面，造成初始内容短暂错误。
3. 策略偏好首屏使用 `Promise.all` 同时等待偏好和生成策略元数据；任一请求变慢都会阻塞全部可信偏好数据。

## 修复内容

1. Skill GET 接口改为纯读取，安装操作只允许由显式安装接口触发，不删除、不重建现有 Skill。
2. Skills 仓库首屏分页为 30 条，提供“加载更多”，搜索仍覆盖名称、摘要、分类及 Skill 内容。
3. 使用单调递增请求编号丢弃过期响应，消除搜索和首次加载竞态。
4. 策略偏好先加载并展示用户偏好，再异步加载算法、质量技术和默认策略元数据。
5. 添加 GET 无副作用、分页和竞态保护回归测试。

## 防回退要求

- 禁止在 Skill 列表、搜索等 GET 请求中执行解压、安装或数据库写入。
- 禁止恢复 SkillsManager 首次挂载的双请求。
- 所有可并发搜索列表必须防止过期响应覆盖当前查询。
- 后台生成任务运行时，Skill 仓库和策略偏好仍必须独立加载。

## 验证结果

- 后端完整测试：372 项通过。
- 前端回归测试：29 项通过。
- Vite 生产构建通过。
- 本地真实数据：512 个 Skill、指令正文约 346 万字符；首屏只返回 30 条，热请求最低约 40ms。
- Playwright：Skill 首屏恰好 30 张卡片并显示“加载更多”；策略偏好不显示加载占位且完整概览可见。
