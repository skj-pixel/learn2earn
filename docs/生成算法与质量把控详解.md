# 生成算法与质量把控详解

> 版本 v2.0 · 对应代码：`backend/app/services/{agentic_product_generator,content_polisher,quality_enhancer,memorybear,rag_service,strategy_compat,generation_task_service,skill_service}.py`

本文档详细说明 Learn2Earn 当前的 7 类生成算法与 6 项质量把控技术的内部原理、调用顺序、组合规则、代码位置（含文件:行号）。

---

## 0. 设计原则：三轴正交解耦

| 轴 | 含义 | 实现位置（代码文件:行号） |
|----|------|---------------------------|
| **Skill** | 用户上传的私有提示词，按 `_skill` 指令拼接到 prompt | `services/skill_service.py:78-138` |
| **生成算法** | 控制 LLM 生成过程的宏观策略（先列大纲再展开、迭代自评、反思式修正等） | `services/agentic_product_generator.py:295-417`（`_plan_product / _generate_product / _polish_with_llm`） |
| **质量技术** | 在生成前后追加的"修正 / 校验 / 检索"步骤 | `services/generation_task_service.py:62-119`（prompt 注入 + 调度） |

兼容性校验位于 `services/strategy_compat.py:144-237`（`validate_combination`）：只产生 `warnings`（咨询），绝不阻断用户组合。

## 1. 生成算法（7 种）

### 1.1 `hierarchical_planning` — 分层规划 ✅ 已实装

**原理**：先把整篇内容拆成"章 → 节 → 段"三层大纲，再用同一 LLM 按大纲逐层展开正文。

**实装位置**：
- `agentic_product_generator.py:295-348` —— `_plan_product(self, ...)`
  - LLM 调用：`max_tokens=1600, temperature=0.4`
  - 输出 JSON 形式的 `Plan`：每章节的标题、目标字数、关键概念列表
- `agentic_product_generator.py:354-417` —— `_generate_product(self, ...)`
  - 按 `Plan.items` 顺序逐章生成
  - `max_tokens=4096-8192, temperature=0.55`（按产品类型自适应）

**优点**：
- 结构稳定，章节目录清晰
- 长文（>5000 字）质量显著高于一次性直出
- 适合 article / course_outline / sop / ppt_outline 等结构化产品

### 1.2 `iterative_refinement` — 迭代精炼 ✅ 已实装

**原理**：生成 → 自评 → 改进 循环。

**实装位置**：
- `agentic_product_generator.py:419-468` —— `_polish_with_llm(self, ...)`
  - LLM 调用：`max_tokens=4096-8192, temperature=0.25`
  - 输入初稿 + 自评 prompt（"请检查段落结构、错别字、标题层级、是否回应了用户问题"）
- `services/content_polisher.py` —— `ContentPolisher.polish_product`
  - 规则化修正：去 prompt 泄漏、合并空段、Markdown 标准化

### 1.3 `chunked_generation` — 分块生成 ⚠️ 占位

**实装位置**：`agentic_product_generator.py:231-289` —— `_build_source_memory(self, ...)._chunk_text`
- 当源文本超过 3200 字时切块（overlap 250）
- 当前实装会**作为生成提示透传**（在 prompt 中追加 chunked 提示），实际仍走 `_plan_product + 主生成`

### 1.4 `parallel_drafting` / `single_pass` / `chunked_parallel` / `reflexion` ⚠️ 占位

均为规划中的算法候选。当用户勾选时，`strategy_compat.validate_combination`（`strategy_compat.py:201-203`）会给出"未实装"的咨询警告，**实际仍跑 `hierarchical_planning + iterative_refinement` 的标准链路**。这是有意为之——允许用户自由探索新组合，而不会因为选了一个未实装项就完全失败。

## 2. 质量技术（11 类，已实装 8 类）

### 2.1 `source_grounding` — 源笔记约束 ✅

**原理**：把当前笔记正文（`note.raw_content[:4000]`）作为唯一事实源；prompt 明确告知"以源笔记为准，不引入未在源中出现的概念"。

**实装位置**：`agentic_product_generator.py:231-289` —— `_build_source_memory(self, ...)`
- 按 3200 字 / 250 字 overlap 切块
- 逐块让 LLM 抽取 bullet
- 拼接为 `## 片段 N`，截断 9000 字

### 2.2 `memorybear` — 长期记忆 ✅

**原理**：参考红熊 AI MemoryBear（PDF 调研 `Super Memory技术调研1785853322799.pdf`），按 5 层记忆 + 艾宾浩斯遗忘曲线 + 3D 反熵增引擎组织用户历史。

**实装位置**：`services/memorybear.py`
- `ebbinghaus_recency()`：第 34-55 行，分段衰减曲线（1d/7d/30d/90d = 1.0/0.7/0.4/0.2/0.1）
- `MemoryItem` 数据类：第 79-99 行
- `importance_score()`：第 66-77 行（编辑 0.5 + 标签 0.2 + 产品引用 0.3，tanh 归一）
- `_score_item()`：第 420-440 行，激活度公式 `0.5*relevance + 0.3*recency + 0.2*importance`，零相关门控
- `run_entropy_engine()`：第 221-256 行（事实合并 + 冲突检测 + 模式抽象）
- `route_memory()`：第 257-289 行（每层限额 + 总字符 10000 上限）
- `route_scene()`：第 291-309 行（MemoryBear vs RAG 场景权重）
- `build_memory_context()`：第 311-419 行（主入口，组装 prompt）
- `memorybear_stats()`：第 460-510 行（全局统计）

**为什么是权威记忆来源**：用户的笔记 / 产品 / 偏好都是真实可信的（用户自己写的）；RAG 检索的外部资料则可能过时或错误。`generation_task_service.py:107-109` 写明"MemoryBear 为权威记忆来源；RAG 退化为外部知识补丁"。

### 2.3 `rag_grounding` — 外部检索 ✅（已实装）

**原理**：按优先级检索外部知识，最终注入 prompt 作为"补丁"。

**实装位置**：`services/rag_service.py`
- `_extract_keywords()`：第 30-58 行（jieba + jieba.analyse 抽取关键词）
- `_score()`：第 60-79 行（命中 token 数 × 标题权重）
- `_call_web_skill()`：第 95-138 行（子进程调 baidu-search / tavily-search 脚本）
- `_user_kb_fallback()`：第 142-186 行（无外部 Skill 时回退用户笔记/产品）
- `retrieve_external_context()`：第 200-269 行（主入口）

**检索链路**：
1. **优先级 1 — Web Skill**：如果用户已安装 `baidu-search` 或 `tavily-search`，且对应 API Key 环境变量（`BAIDU_API_KEY` / `TAVILY_API_KEY`）存在，调用 Skill 自带脚本子进程拉取实时资料
2. **优先级 2 — 用户知识库兜底**：外部不可用时，把用户的其他笔记 / 产品当作"知识库"，按关键词命中数排序，取 Top 6
3. **优先级 3 — 无命中**：prompt 标注"无外部上下文"

### 2.4 `quality_scoring` — 质量打分 ✅

**实装位置**：`services/quality_enhancer.py`
- `QualityEnhancer.score()`：第 80-145 行（综合分数）
- 三项指标加权合并：`overall_score = 0.7 * hallucination + 0.15 * coherence + 0.15 * seo`

### 2.5 `hallucination_check` — 幻觉检测 ✅

**实装位置**：`services/quality_enhancer.py::QualityEnhancer.check_hallucination`
- 与 `quality_scoring` 共享算法但产出更细的 `findings[]`，列出具体可疑句
- 扣分项：新增未提及事实、内部矛盾、与源笔记冲突的数值

### 2.6 `seo_optimization` — SEO 优化 ✅

**实装位置**：`services/quality_enhancer.py::QualityEnhancer.seo`
- 生成关键词密度、首段长度、H2/H3 比例、内链建议等
- 适合 article / xiaohongshu_sop / script 等需要平台曝光的产品

### 2.7 `few_shot` — 少样本示例 ✅

**实装位置**：`services/agentic_product_generator.py:_build_prompt`
- 根据产品类型注入 1-2 个示例输出片段
- 帮助 LLM 稳定输出风格

### 2.8 `temperature_scheduling` — 温度调度 ✅

**实装位置**：`services/agentic_product_generator.py:_generate_product`
- 不同阶段用不同 temperature：规划 0.4 / 主生成 0.55 / 精炼 0.25
- 平衡创造性 vs 一致性

### 2.9 `coherence_validation` — 连贯性验证 ✅

**实装位置**：`services/quality_enhancer.py::QualityEnhancer.coherence`
- 检查章节顺序、上下文连贯性、段落衔接词
- 产出连贯性分数（0-1）

### 2.10 `auto_restructuring` — 自动分段重组 ✅

**实装位置**：`services/content_polisher.py::ContentPolisher.restructure`
- 把超长段落拆分、为过短段落补全上下文
- 确保每段 100-300 字

### 2.11 `audience_role_injection` / `competitor_differentiation` ⚠️ 占位

规划中的技术，勾选后会通过 `strategy_compat.validate_combination` 给出咨询警告。

## 4. 调用顺序（`generation_task_service._run_task` 流水线）

**实装位置**：`services/generation_task_service.py:67-145` —— `_run_task(self, task, user)`

```
1. read note & subject                                  （第 70-72 行）
   ↓
2. build_skill_prompt(skills)                           （第 74-79 行：Skill 注入）
   ↓
3. if "memorybear" in techniques:
       context = memorybear.build_memory_context(...)   （第 82-87 行：MemoryBear 注入）
   ↓
4. if "rag_grounding" in techniques:
       rag_context = rag_service.retrieve_external_context(...)
                                                       （第 89-94 行：RAG 注入）
   ↓
5. note_assets = list(note_id) 按 source_anchor 排序    （第 96-100 行：图片引用注入）
   ↓
6. validate_combination(...) 警告不阻断                 （第 102-104 行）
   ↓
7. for product_type in types:                           （第 106-114 行：批量生成）
       analyze_content(note_content)
       build_source_memory(...)
       _plan_product(...)        # hierarchical_planning
       _generate_product(...)    # 主生成
       _polish_with_llm(...)     # iterative_refinement
       ContentPolisher.polish_product
       QualityEnhancer.check(...) # quality_scoring + hallucination_check + seo_optimization
       _strip_prompt_leakage(text)
       save product with generation_meta（写 skill_names / algorithms / techniques / memorybear / strategy_warnings）
```

## 5. 三层记忆 × RAG 的场景路由

**实装位置**：`services/memorybear.py:291-309` —— `route_scene(self, query, has_user_history)`

| 场景 | MB 权重 | RAG 权重 | 触发条件 |
|------|---------|----------|----------|
| 用户积累丰富 | 0.8 | 0.2 | ≥2 条相关笔记 或 ≥1 个相关产品 |
| 外部知识需求 | 0.3 | 0.7 | 查询含外部关键词（定义 / 教程 / API / 标准 / 论文） |
| 默认平衡 | 0.5 | 0.5 | 其他情况 |

`generation_task_service.py` 默认同时启用 `memorybear + rag_grounding`，让 LLM 自适应选择权重。

## 6. 矛盾检测（前端 UX）

**实装位置**：`frontend/src/components/ProductGenerator.jsx:193-197` —— `compatibilityWarnings`
**实装位置**：`frontend/src/components/ProductLibrary.jsx:210-260` —— `StrategyMap` 子组件

`strategy_compat.validate_combination` 返回 `warnings` 列表，前端在产品库的每个产品卡片下用红色 `⚠️ 策略警告 N` 标签展示，hover 看具体冲突内容。

**当前已知的"自相矛盾"典型场景**：
- 选了 `chunked_generation + single_pass`（一个要分块、一个要单次）→ warning
- LLM 未配置但选了任何 `needs_llm: true` 的算法 → warning
- 选了未安装的 Skill ID → warning

## 8. 图片引用（任务 4 衔接）

**实装位置**：`services/generation_task_service.py:96-100`

`NoteAsset` 是从导入笔记时提取的图片（`routers/workspace.py:62` 的 `/api/notes/{note_id}/images` 路由）。`enqueue_generation` 查所有 `note_id` 关联的 `NoteAsset`，按 `source_anchor` 排序后拼成 Markdown 段塞进 prompt，要求 LLM 用 `[插图 N: filename]` 语法引用。

`docx_service.py::export_product_docx` 解析时把 `[插图 N: filename]` 还原为内嵌图片。
